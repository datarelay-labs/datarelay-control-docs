# 스크린샷으로 따라 하는 Stream Wizard

<Warning>
여기 표시된 이미지는 Control의 **기존 실제 UI 테스트 캡처**를 잘라 번호를 표시한 것입니다. 화면에는 과거 **6단계 Wizard**가 보이지만, 현재 제품의 기본 구성 순서는 **Connect → Sample & Record Selection → Destinations → Route Processing → Deploy**입니다. 따라서 캡처 속 과거 단계 번호나 메뉴 순서를 그대로 따라 하지 말고, 현재 UI에서 같은 기능을 찾으세요. 스크린샷은 성공적인 실제 전송을 보장하지 않습니다.
</Warning>

**사전 준비:** [커넥터별 실습 목차](/ko/use-cases/index)에서 Vendor API 문서·인증 정보·비식별 샘플을 준비하고, 실제 수신 가능한 Destination을 구성해 두세요.


## 1. 저장된 Connector 선택

Connector를 사전에 생성하고 **Connect**에서 저장된 Connector를 선택합니다. 이미 선택한 경우에는 실제 Vendor/Source 정보를 확인합니다.

![select-connector — numbered Control historical UI capture](/images/screenshots/annotated/select-connector.webp)

*그림 1. **기존 Connector를 선택하는 화면.** ① Saved Connector 목록에서 미리 만든 Connector를 선택합니다(캡처의 Generic REST는 예시). ② 다음 Sample 단계로 이동합니다. 상단 Connector 탭은 이미 선택된 상태입니다.*

## 2. 수집 테스트 실행

**Run Test**로 샘플을 가져와 HTTP 상태와 레코드 수를 확인합니다. 성공했다고 해서 다음 단계의 필수 필드를 자동 선택한 것은 아닙니다.

![run-test — numbered Control historical UI capture](/images/screenshots/annotated/run-test.webp)

*그림 2. **실제 수집 테스트와 레코드 수 확인.** ① Run Test 실행 → ② HTTP 상태와 추출 레코드 수 확인 → ③ 성공하면 Record Selection으로 이동합니다. API 호출 성공만으로 Destination 전송이 증명되지는 않습니다.*

## 3. 이벤트 경로와 Checkpoint 확정

JSON Tree에서 실제 이벤트 배열을 선택합니다. 고유 ID와 시간 필드의 안정성도 확인한 뒤 Checkpoint를 지정합니다. 자동 추천은 사용자 확인이 필요합니다.

![record-selection — numbered Control historical UI capture](/images/screenshots/annotated/record-selection.webp)

*그림 3. **레코드 경로와 Checkpoint 선택.** ① 추천 Record Path를 검토하고 ② JSON Tree에서 실제 이벤트 필드를 확인한 다음 ③ Checkpoint Field를 지정합니다. 이 화면은 미확정 상태이므로 경고가 표시되어 있습니다.*

## 4. 매핑된 최종 JSON 확인

**Route Processing / Transform**의 Sample, Mapping, Preview를 비교합니다. 현재 UI에서는 Destination 선택 이후 Route별 처리를 구성합니다.

![field-mapping — numbered Control historical UI capture](/images/screenshots/annotated/field-mapping.webp)

*그림 4. **원본 이벤트를 대상 필드로 매핑.** ① Sample Event의 원본값 확인 → ② Field Mapping에서 대상 필드 매핑 → ③ Final Event Preview의 출력값 비교. Preview는 실제 전송 증빙이 아닙니다.*

## 5. 추가 필드 설정

필요하면 **Add field → Static Value**를 선택합니다. 메뉴를 닫은 뒤 Preview에서 예상 필드가 나타나는지 확인하세요.

![add-static-field — numbered Control historical UI capture](/images/screenshots/annotated/add-static-field.webp)

*그림 5. **Route에서 사용자 정의 필드 추가.** ① Add field를 누르고 ② Static Value를 선택합니다. ③ 메뉴를 닫은 다음 Final Event Preview에서 추가 필드가 반영됐는지 확인합니다.*

## 6. 배포 전 차단 조건 해결

Deploy에서 **NEEDS ATTENTION**이 보이면 Data/Records의 **Edit**로 돌아가 오류를 해결합니다. 차단 상태에서는 Stream을 활성화하지 않습니다.

![deploy-readiness — numbered Control historical UI capture](/images/screenshots/annotated/deploy-readiness.webp)

*그림 6. **Deploy가 차단되었을 때 수정할 위치.** ① NEEDS ATTENTION을 확인합니다. ② Data·Records 항목의 Edit로 돌아가 수집/경로 설정을 수정합니다. ③ 배포 버튼이 비활성이라면 계속 진행하지 않습니다.*

## 7. 배포 후 실제 실행 확인

Stream 생성 후 **Start Stream**과 **View logs**를 사용하여 실제 실행을 확인합니다. 이 캡처의 **Runtime API unavailable** 문구는 실행 성공이 확인되지 않았음을 의미합니다.

![stream-actions — numbered Control historical UI capture](/images/screenshots/annotated/stream-actions.webp)

*그림 7. **Stream 생성 후 실행 및 로그 확인.** ① Stream 생성 결과 확인 → ② 실제 Runtime이 정상일 때 Start Stream → ③ View logs에서 Run과 Route 결과 확인. 캡처에는 Runtime API unavailable이 표시되므로 실제 전송 성공 증거는 아닙니다.*

## 8. 운영 상태 조사

Dashboard 조회 기간, Health, Alerts를 보고 문제 Stream을 찾습니다. 실제 전달은 Route Logs와 수신 시스템 데이터를 대조해야 확인됩니다.

![dashboard-triage — numbered Control historical UI capture](/images/screenshots/annotated/dashboard-triage.webp)

*그림 8. **Dashboard에서 장애 Stream 추적 시작.** ① 조회 기간을 설정하고 ② Health의 Critical/Warning을 확인한 다음 ③ Recent Alerts를 열어 영향 범위를 찾습니다. 근본 원인은 Streams·Routes·Logs에서 확인합니다.*

## 오류 예시: Source API HTTP 503

이 오류는 **Source 수집 테스트 오류**이지 Destination 오류가 아닙니다. HTTP Status와 Vendor API 상태를 확인한 뒤 재시도하세요.

![source-api-error — numbered Control historical UI capture](/images/screenshots/annotated/source-api-error.webp)

*그림 9. **Source API가 HTTP 503을 반환한 경우.** ① HTTP 503 응답과 오류 메시지 확인 → ② Source/API 문제를 고친 뒤 Retry → ③ 다음 단계가 차단된 상태에서는 진행하지 않습니다. 이 화면은 Destination 장애가 아닌 Source API Test 실패입니다.*

## 보조 기능: 이전 임시 저장 복구

임시 저장된 설정을 보존하려면 **Resume draft**를 선택합니다. **Start fresh**는 새 작업을 시작할 때만 사용합니다.

![saved-draft — numbered Control historical UI capture](/images/screenshots/annotated/saved-draft.webp)

*그림 10. **임시 저장된 Wizard 재개.** ① Resume draft로 기존 설정을 계속하거나 ② Start fresh로 새 작업을 시작합니다. 이미 저장한 입력값을 보존하려면 Resume draft를 선택하세요.*

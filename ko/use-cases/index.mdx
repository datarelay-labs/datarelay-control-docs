# 활용 사례별 실습

원하는 결과에 따라 안내서를 선택하세요. 모든 가이드는 **사전 조건 → 실제 화면에서 누를 항목 → 예시 입력 → 성공 확인 → 실패 시 조치** 순서로 작성했습니다. 기준 제품은 `datarelay-labs/datarelay-control` **main-v2 @ f7ae7b35 (2026-10-18)**입니다.

<Warning>
실습은 비운영 환경에서 가상 이벤트로 진행하세요. 실제 API Token, 고객 개인정보, 운영 로그는 입력하지 마세요. 전체 사용자 브라우저 검증은 [제품 이슈 #413](https://github.com/datarelay-labs/datarelay-control/issues/413)에서 진행 중입니다. Preview 성공만으로 실제 전송 성공을 판단하지 않습니다.
</Warning>

**실제 화면을 보며 따라하려면:** [번호·설명이 표시된 Stream Wizard 스크린샷 가이드](/ko/use-cases/screen-walkthrough)에서 Connector 선택부터 배포·로그 확인까지 진행하세요.

## 커넥터별 따라하기: 먼저 준비하고 나중에 실행하기

**① Vendor API/연동 가이드 확인 → ② 접속·인증·권한·샘플 준비 → ③ 모르면 ChatGPT에 공개 문서와 비식별 샘플로 질문 → ④ Connector 생성·연결 테스트 → ⑤ Destination 생성 → ⑥ Stream/Record Selection/Checkpoint → ⑦ Mapping·Masking·지원되는 Tokenization → ⑧ Deploy → ⑨ Logs와 실제 수신 시스템 검증 → ⑩ 장애·Schema Drift 대응** 순서로 진행합니다.

각 Connector 페이지 첫 부분에 이 절차와 필요한 입력값, ChatGPT 질문 예시, 장애 대응을 추가했습니다. 실제 제품 화면으로 검증된 스크린샷만 사용하며, 인증된 내부 화면이 확보되지 않은 단계에 가짜 화면을 넣지 않습니다.

## 제품 구성과 기본 순서

```text
Source / Connector → Stream → Route A → Destination A
                            └→ Route B → Destination B
```

Stream은 실행 단위, Route는 목적지별 처리 단위입니다. 목적지별로 변환이나 보호 정책이 달라도 Stream을 여러 개 만들 필요가 없습니다.

**Connect → Sample & Record Selection → Destinations → Route Processing → Deploy** 순서로 구성합니다.

모든 실습의 완료 기준은 설정 저장만이 아니라 **실제 Run, Route 전달 로그, 수신 시스템의 데이터**까지 비교하는 것입니다. [첫 Stream](/ko/getting-started/first-stream), [Route Processing](/ko/processing/route-processing), [알려진 제한](/ko/reference/limitations)도 참고하세요.

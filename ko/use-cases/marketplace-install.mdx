# Marketplace를 이용해 Connector 구성하기

**목표:** 지원되는 패키지를 활용하여 통합 기능을 준비하고 실제 Stream을 배포합니다. 패키지 설치와 데이터 수집 실행은 서로 다른 작업입니다.

<Warning>
Marketplace Lifecycle, Signing, Registry, AI Builder는 현재 **개발 브랜치**에 존재하는 기능입니다. 고정된 GA 릴리스에서 모두 검증된 것으로 간주하지 않습니다. UI 메뉴나 Install 버튼이 없으면 해당 버전에서는 제공되지 않는 것이므로 기존 Built-in Connector를 사용하세요.
</Warning>

## 적용 순서

이 사례는 이미 구성된 Connector·Destination·Stream을 전제로 합니다. 아직 생성하지 않았다면 [커넥터별 수집 가이드](/ko/use-cases/index)에서 먼저 수집 Source를 설정하세요. 이후 이 페이지의 구체적인 단계를 수행하고 **실제 Logs와 Destination/격리 기록**을 검증합니다. 화면 캡처는 기존 테스트 증빙으로, 실제 결과를 대신하지 않습니다.


## 1. 통합 패키지 선택

1. **Connectors** (`/connectors`)에서 배포된 버전이 제공하는 **Marketplace / Browse Integrations** 메뉴를 찾습니다. 패키지 관리 화면은 **Administration → Connector Catalog** (`/admin/connector-catalog`)에 나타날 수도 있습니다.
2. 사용하려는 Vendor/Product를 검색합니다.
3. 세부 화면에서 **패키지 Origin, Package Version, Vendor API Version, 제공 Streams, 인증 방식, 호환성, License/Provenance, Trust/Support Tier**를 확인합니다.
4. `Imported` 또는 `Community` 상태를 실제 Vendor API까지 검증한 `Verified`와 동일하게 취급하지 않습니다.

## 2. 검증하고 설치

1. Built-in 또는 조직이 승인한 패키지를 선택합니다.
2. Validation 경고와 플랫폼 호환성을 확인하고 차단 오류가 있으면 해결합니다.
3. 가능한 경우 **Install**을 선택합니다. 오프라인 설치는 현재 버전과 관리자 정책이 지원하는 Upload/Signed Bundle 경로만 사용합니다.
4. Registry에 Installed Version이 표시되는지 확인합니다.

**Install만으로 Credential 생성, Stream Enable, Polling 시작, 실행 중 Stream 수정, Checkpoint 갱신이 발생해서는 안 됩니다.**

패키지 YAML/JSON에는 Secret이나 임의 실행형 Python/JavaScript/Shell 코드를 넣지 않습니다.

## 3. 실제 수집 Stream 만들기

1. **Connectors**로 돌아가 패키지에서 제공하는 Connector/Preset을 선택합니다.
2. 별도의 **Credential**을 지원되는 인증 방식으로 구성합니다.
3. `/streams/new`의 **Connect**에서 해당 Connector를 지정합니다.
4. **Run Test**로 자신의 Vendor 계정에 실제 호출하고 응답을 확인합니다.
5. **Record Selection**에서 현재 이벤트 구조와 Event Root를 확정합니다. Package Sample/Schema는 초기 자료일 뿐 **실제 API 응답이 우선**입니다.
6. 테스트 Destination을 선택하고 Route Processing, Effective Preview를 확인합니다.
7. **Deploy** 후 필요한 경우 Stream을 Enable/Start합니다.
8. **Logs**의 Route 전송 기록과 실제 Destination 수신을 함께 확인합니다.

## 4. 업그레이드와 롤백 시 주의

**Upgrade / Rollback / Uninstall** 전에는 의존 중인 Stream, Mapping, API Version 호환성과 변경 영향을 확인합니다. 패키지 업데이트가 실행 중 Stream이나 Schema Baseline을 자동 변경하지 않아야 하며, Rollback이 이미 전송한 이벤트나 Checkpoint까지 되돌리지는 않습니다.

## 완료 조건

**패키지 신뢰도/버전 확인 → 설치 상태 확인 → 별도 Credential 생성 → Stream 실제 샘플 확인 → Route 전달/독립 수신 증명**까지 완료해야 합니다. 설치 성공만으로 완료가 아닙니다.

해당 Vendor의 패키지를 찾을 수 없다면 [HTTP API Polling](/ko/use-cases/http-api)으로 범용 Connector를 구성합니다. [Connectors & Marketplace](/ko/administration/connectors-marketplace), [제한 사항](/ko/reference/limitations)도 참고하세요.

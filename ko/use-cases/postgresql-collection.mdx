# PostgreSQL 테이블의 로그를 수집하기

**목표:** Control의 **Database query (PostgreSQL)** Connector로 테스트 테이블을 읽어 HTTP Destination에 전달합니다. 사용자가 관리하는 **테스트 DB**가 필요합니다.

## 1. 테스트 테이블 준비

승인된 테스트 PostgreSQL DB에서 다음 SQL을 실행합니다.

```sql
CREATE TABLE IF NOT EXISTS control_tutorial_events (
    id bigint PRIMARY KEY,
    occurred_at timestamptz NOT NULL,
    message text NOT NULL
);
INSERT INTO control_tutorial_events(id, occurred_at, message)
VALUES (101, '2026-10-18T00:00:00Z', 'synthetic db event')
ON CONFLICT (id) DO NOTHING;
```

별도 읽기 전용 DB 계정을 만들고 테이블에 `SELECT` 권한만 부여합니다. Control 서버에서 DB 포트에 접근 가능해야 합니다.

## 2. Connector 설정

1. **Connectors → Create Connector → Database query (PostgreSQL)**을 선택합니다.
2. **Connector Name** = `Lab PostgreSQL`, **DB type** = `PostgreSQL`을 지정합니다.
3. 실제 **Host**, **Port**(보통 5432), **Database name**, **Username**, **Password**를 입력합니다.
4. 서버 인증서 정책에 맞는 **SSL mode**를 설정합니다. 운영 인증서가 존재한다면 `VERIFY_FULL` 같은 검증 옵션을 사용합니다.
5. 저장하고 지원되는 DB Connectivity Test를 실행해 권한/TLS/네트워크를 확인합니다.

## 3. SQL Query와 Sample 확인

1. `/streams/new`에서 저장한 Connector를 선택합니다.
2. **Connect/Run Test**의 DB Discovery 또는 Query Builder에서 읽기 전용 Query를 구성합니다.

```sql
SELECT id, occurred_at, message
FROM control_tutorial_events
ORDER BY occurred_at, id
```

3. **Run Test**에서 샘플 1건 이상을 확인하고 **Record Selection**에서 반환 레코드를 선택합니다.
4. Union Schema와 필드 타입을 확인합니다.
5. 증분 수집을 사용한다면 안정적인 Cursor/정렬과 ID Tie-breaker를 갖추고 Checkpoint를 명시적으로 검증합니다. 시간 필드가 있다고 자동으로 올바른 Cursor가 되는 것은 아닙니다.

## 4. 전송 확인

1. [테스트 HTTP 수신기](/ko/use-cases/lab-setup)를 `WEBHOOK_POST` Destination으로 선택합니다.
2. **Route Processing**에서 Mapping/Preview를 검토하고 **Deploy**를 수행합니다.
3. Stream을 실행한 후 **Logs**와 `received-9011.ndjson`에서 해당 DB 이벤트를 찾습니다.
4. 추가 가상 Row를 삽입한 뒤 재수집하여 중복이나 누락이 없는지도 검증합니다.

**완료 조건:** DB 테스트 Query 성공, Route 전달 로그, 독립 HTTP 수신 파일에 동일한 이벤트 존재.

## 실패 시

- 연결 실패: DB Host/Port, SSL, 계정 및 권한 확인
- Query 0건: DB/Schema/Table과 WHERE 조건 확인
- 중복/누락: 정렬, Checkpoint와 Tie-breaker 확인
- PostgreSQL이 아닌 DB: 현재 확인된 Query Runtime은 PostgreSQL 중심이므로 추가 엔진 지원을 가정하지 않습니다.

# SFTP 서버의 로그 파일을 수집하기

**목표:** 테스트 SFTP 서버의 JSONL 파일을 읽어 Stream/Route로 전달합니다. `SFTP-compatible SCP`는 별도 모드이며 일반적인 구형 SCP Directory Polling과 동일하지 않습니다.

## 시작 전: SFTP 연동 정보 준비

아래 정보를 먼저 준비해야 Connector와 Stream 설정 도중 중단되지 않습니다.

1. **제품 API/연동 가이드 확인:** SSH host/port, username, read-only path, host key fingerprint, password or private key, file rotation. Vendor 공식 API 문서에서 실제 Endpoint, 인증 방법, 응답 샘플과 데이터 수집 제한을 확인합니다.
2. **권한·네트워크 확인:** 읽기 전용/최소 권한 계정과 Control 서버에서 Source에 도달하는 네트워크를 준비합니다. 운영 Secret을 문서나 ChatGPT에 붙여넣지 않습니다.
3. **데이터 정의 확인:** 실제 샘플 2~5개(개인정보 제거), 이벤트 배열/필드명, 시간·ID, 페이지 처리와 중복 방지 기준을 정리합니다.
4. **목적지 정보 준비:** 수신 시스템의 IP/URL, Port, Protocol, TLS 및 인증, 정상 수신 확인 방법을 준비합니다.
5. **모르겠다면 ChatGPT 활용:** Vendor API 문서의 공개된 부분과 비식별 샘플을 이용해 필수 Connector 항목·API Request·Record Root·Checkpoint 후보를 정리합니다. **생성된 설정은 공식 문서 및 Run Test로 검증**해야 합니다.

### ChatGPT에 물어볼 예시

> DataRelay Control의 Remote file polling Connector로 로그를 수집하려고 합니다. 아래 공개 API 설명과 비식별 샘플을 기준으로 ① 필요한 인증/접속 정보 ② Request·Pagination ③ Event Root와 주요 필드 ④ Checkpoint 후보와 중복 위험 ⑤ Destination으로 전송하기 전 확인할 사항을 표로 정리해 주세요. 문서에서 확인되지 않은 정보는 추정하지 말고 확인 필요로 표시해 주세요.

## 처음부터 끝까지 따라하기: 공통 작업 순서

1. **Connector 생성:** Connectors → Create Connector → **Remote file polling**. 준비한 정보로 SFTP protocol, Host, Username, strict known-hosts policy, remote file selector을(를) 입력합니다. 저장 후 제공되는 연결 테스트를 실행합니다.
2. **Destination 생성:** Destinations → Create에서 실제 수신 시스템 유형(SYSLOG_UDP/TCP/TLS 또는 WEBHOOK_POST)을 선택하고 Host/Port/URL/TLS/인증을 설정합니다. 독립 테스트 수신기로 먼저 확인하는 것을 권장합니다.
3. **Stream 생성:** Streams → Create → **Connect**에서 방금 만든 Connector를 선택하고 API/파일/DB 수집 조건을 지정합니다.
4. **Sample & Record Selection:** Run Test로 실제 데이터가 수집되는지 확인합니다. Event Root, 추출 레코드, Union Schema, Checkpoint와 중복 처리 기준을 확인합니다.
5. **Destinations:** 준비한 Destination을 선택하여 Route를 생성합니다.
6. **Route Processing:** Mapping/Transform에서 필드명·시간·추가 필드를 확인합니다. 필요하면 개인정보 **Mask**, **Tokenize**(현재 버전에서 실제 제공되는 경우에만), Remove/Drop, Quarantine/Block을 선택합니다. Route별 Inherit/Override 및 Effective Status를 확인합니다. 보호 기능을 단순히 켰다고 실제 출력이 보호되었다고 가정하지 않습니다.
7. **Deploy 및 실행:** Readiness 경고를 해결하고 저장·배포 후 Stream을 실행합니다.
8. **최종 검증:** remote listing/read, parsed records, rotation/checkpoint and sink receipt. **Run ID, Route Delivery Log, 실제 수신 시스템의 데이터**를 대조합니다.

### 실패·스키마 변경 시

- **접속/인증 실패:** DNS/방화벽/TLS, Token 만료, API 권한, 호출 제한을 확인합니다.
- **수집은 됐으나 레코드 0건:** 응답 Envelope, Record Root, Pagination, 파일 포맷을 다시 확인합니다.
- **전송 실패:** Streams → Routes → Logs 순서로 Run/Route/Destination, Policy, Retry를 조사하고 [전송 장애 가이드](/ko/use-cases/delivery-incident)를 수행합니다.
- **새 필드/타입 변경:** Union Schema의 Observed/Confirmed 상태, Field Path, Unknown Field 정책과 Route Override를 검토하고 [Schema Drift 가이드](/ko/use-cases/schema-change)를 수행합니다.
- **마스킹·토크나이징 미적용:** 실제 버전의 지원 여부, Rule 저장, Effective Status, 최종 Destination Payload를 확인합니다. Preview만으로 성공 처리하지 않습니다.

## 1. 원격 파일 준비

1. 테스트용 SSH 서버에 `/srv/control-demo/events.jsonl` 파일을 만들고 다음 한 줄을 저장합니다.
```json
{"id":"sftp-001","message":"remote file record","severity":"low"}
```
2. 해당 경로에 읽기/목록 권한만 가진 SSH 계정을 만듭니다.
3. 일반 `sftp` 클라이언트로 접속과 파일 읽기를 먼저 확인합니다.
4. 서버 SSH Host Key Fingerprint를 확인해 기록합니다. 연결 테스트 때문에 Host Key 검증을 끄지 않습니다.

## 2. Remote File Connector 생성

1. **Connectors → Create Connector → Remote file polling (SFTP / SFTP-compatible SCP mode)**을 선택합니다.
2. **Connector Name** = `Lab SFTP`, **Protocol** = `sftp`를 입력합니다.
3. 실제 **Host**, **Port**(보통 22), **Username**을 입력합니다.
4. 허가된 **Password 또는 Private key**를 설정합니다.
5. **Known hosts**에 검증한 호스트 키를 구성하고 검증 Policy는 **strict**를 사용합니다.
6. 제공되는 원격 디렉터리/파일 선택 항목에서 `/srv/control-demo/events.jsonl` 파일을 대상으로 합니다.
7. 저장한 뒤 지원되는 Remote Connection/List Test로 파일을 조회합니다.

## 3. Stream과 전송

1. `/streams/new`에서 `Lab SFTP` Connector를 선택하고 **Run Test**를 실행합니다.
2. `sftp-001` 이벤트 레코드가 추출되는지 **Record Selection**에서 확인합니다.
3. [테스트 Destination](/ko/use-cases/lab-setup)를 지정한 후 Route Processing과 Deploy를 완료합니다.
4. Stream을 실행하고 **Logs**의 Route 결과와 실제 수신 파일을 비교합니다.

**완료 조건:** SFTP 파일 목록/읽기, 이벤트 추출, 독립 Destination 수신 성공이 일치합니다.

## 실패 시

- Host Key 오류: 실제 Host Fingerprint와 Known hosts를 수정합니다. 비보안 검증으로 우회하지 않습니다.
- Permission denied: SSH 계정의 디렉터리/파일 읽기 권한 확인
- 레코드 0건: 파일 인코딩/JSONL 형식/Record Root 확인
- 이벤트 중복: 파일 Rotation 및 Checkpoint/읽기 위치 확인

# AWS S3 또는 MinIO 로그 파일 수집하기

**목표:** S3 호환 버킷의 가상 이벤트 파일을 수집하고 Stream/Route를 통해 전송합니다.

## 시작 전: S3 / MinIO 연동 정보 준비

아래 정보를 먼저 준비해야 Connector와 Stream 설정 도중 중단되지 않습니다.

1. **제품 API/연동 가이드 확인:** endpoint/region/bucket/prefix/object pattern, read/list IAM permission, path-style and TLS. Vendor 공식 API 문서에서 실제 Endpoint, 인증 방법, 응답 샘플과 데이터 수집 제한을 확인합니다.
2. **권한·네트워크 확인:** 읽기 전용/최소 권한 계정과 Control 서버에서 Source에 도달하는 네트워크를 준비합니다. 운영 Secret을 문서나 ChatGPT에 붙여넣지 않습니다.
3. **데이터 정의 확인:** 실제 샘플 2~5개(개인정보 제거), 이벤트 배열/필드명, 시간·ID, 페이지 처리와 중복 방지 기준을 정리합니다.
4. **목적지 정보 준비:** 수신 시스템의 IP/URL, Port, Protocol, TLS 및 인증, 정상 수신 확인 방법을 준비합니다.
5. **모르겠다면 ChatGPT 활용:** Vendor API 문서의 공개된 부분과 비식별 샘플을 이용해 필수 Connector 항목·API Request·Record Root·Checkpoint 후보를 정리합니다. **생성된 설정은 공식 문서 및 Run Test로 검증**해야 합니다.

### ChatGPT에 물어볼 예시

> DataRelay Control의 S3 Object Polling Connector로 로그를 수집하려고 합니다. 아래 공개 API 설명과 비식별 샘플을 기준으로 ① 필요한 인증/접속 정보 ② Request·Pagination ③ Event Root와 주요 필드 ④ Checkpoint 후보와 중복 위험 ⑤ Destination으로 전송하기 전 확인할 사항을 표로 정리해 주세요. 문서에서 확인되지 않은 정보는 추정하지 말고 확인 필요로 표시해 주세요.

## 처음부터 끝까지 따라하기: 공통 작업 순서

1. **Connector 생성:** Connectors → Create Connector → **S3 Object Polling**. 준비한 정보로 S3 Endpoint URL, Bucket, Prefix, Object key pattern, Access key and Secret key을(를) 입력합니다. 저장 후 제공되는 연결 테스트를 실행합니다.
2. **Destination 생성:** Destinations → Create에서 실제 수신 시스템 유형(SYSLOG_UDP/TCP/TLS 또는 WEBHOOK_POST)을 선택하고 Host/Port/URL/TLS/인증을 설정합니다. 독립 테스트 수신기로 먼저 확인하는 것을 권장합니다.
3. **Stream 생성:** Streams → Create → **Connect**에서 방금 만든 Connector를 선택하고 API/파일/DB 수집 조건을 지정합니다.
4. **Sample & Record Selection:** Run Test로 실제 데이터가 수집되는지 확인합니다. Event Root, 추출 레코드, Union Schema, Checkpoint와 중복 처리 기준을 확인합니다.
5. **Destinations:** 준비한 Destination을 선택하여 Route를 생성합니다.
6. **Route Processing:** Mapping/Transform에서 필드명·시간·추가 필드를 확인합니다. 필요하면 개인정보 **Mask**, **Tokenize**(현재 버전에서 실제 제공되는 경우에만), Remove/Drop, Quarantine/Block을 선택합니다. Route별 Inherit/Override 및 Effective Status를 확인합니다. 보호 기능을 단순히 켰다고 실제 출력이 보호되었다고 가정하지 않습니다.
7. **Deploy 및 실행:** Readiness 경고를 해결하고 저장·배포 후 Stream을 실행합니다.
8. **최종 검증:** object listing, sample record extraction, checkpoint and sink receipt. **Run ID, Route Delivery Log, 실제 수신 시스템의 데이터**를 대조합니다.

### 실패·스키마 변경 시

- **접속/인증 실패:** DNS/방화벽/TLS, Token 만료, API 권한, 호출 제한을 확인합니다.
- **수집은 됐으나 레코드 0건:** 응답 Envelope, Record Root, Pagination, 파일 포맷을 다시 확인합니다.
- **전송 실패:** Streams → Routes → Logs 순서로 Run/Route/Destination, Policy, Retry를 조사하고 [전송 장애 가이드](/ko/use-cases/delivery-incident)를 수행합니다.
- **새 필드/타입 변경:** Union Schema의 Observed/Confirmed 상태, Field Path, Unknown Field 정책과 Route Override를 검토하고 [Schema Drift 가이드](/ko/use-cases/schema-change)를 수행합니다.
- **마스킹·토크나이징 미적용:** 실제 버전의 지원 여부, Rule 저장, Effective Status, 최종 Destination Payload를 확인합니다. Preview만으로 성공 처리하지 않습니다.

## 1. 테스트 객체 업로드

테스트용 MinIO 또는 AWS S3 버킷에 `security/tutorial.jsonl` 객체를 만들고 다음 내용을 저장합니다.

```json
{"id":"s3-001","message":"object event one","severity":"low"}
```

Control Runtime이 해당 S3 Endpoint에 접근할 수 있어야 합니다. 테스트 권한은 읽기/목록 조회만 부여하고 운영 키를 문서나 Package에 포함하지 않습니다.

## 2. S3 Connector 생성

1. **Connectors → Create Connector → S3 Object Polling (MinIO / AWS-compatible)**을 선택합니다.
2. **Connector Name** = `Lab S3 Events`를 입력합니다.
3. **S3 endpoint & bucket**에서 실제 **Endpoint URL**, **Bucket**, **Region**을 입력합니다.
4. **Prefix** = `security/`, **Object key pattern** = `*.jsonl`을 예시로 설정합니다. 실제 Object Key 구조와 일치하도록 확인합니다.
5. **Access key**, **Secret key**를 Connector의 보호되는 입력 항목에 설정합니다.
6. MinIO는 필요하면 **Path-style addressing**을 켭니다. 보안이 필요한 네트워크에서는 올바른 인증서와 HTTPS를 사용합니다.
7. 저장 후 지원되는 S3 연결/목록 테스트로 지정한 객체가 조회되는지 확인합니다.

## 3. Stream 구성

1. `/streams/new`의 **Connect**에서 `Lab S3 Events`를 선택합니다.
2. **Sample & Record Selection**에서 테스트 후 JSONL 레코드가 올바르게 추출되는지 확인합니다.
3. Event Root와 Union Schema를 점검하고 지원되는 Checkpoint/객체 진행 정책을 구성합니다.
4. [테스트 HTTP Destination](/ko/use-cases/lab-setup)를 선택합니다.
5. **Route Processing → Deploy**를 수행하고 Stream 실행 상태를 확인합니다.
6. **Logs**와 실제 HTTP 수신 파일에서 `s3-001`을 찾습니다.

**완료 조건:** S3 객체 발견, 레코드 추출, Route 전송 성공, 독립 수신 결과가 모두 일치합니다.

## 실패 시

- 객체 목록 없음: Bucket/Prefix/Object key pattern/권한 확인
- Endpoint/TLS 실패: Region, URL, 인증서 및 네트워크 확인
- 객체는 읽혔지만 레코드 0건: JSONL/배열/객체 형식과 Record Selection 확인
- 객체 반복 수집: Checkpoint와 객체 식별 처리 확인

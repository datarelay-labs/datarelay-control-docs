# Collect Logs from S3 or MinIO

**Goal:** read a synthetic event file from an S3-compatible bucket and deliver its records through a Stream.

## Before you start: collect S3 / MinIO integration requirements

1. **Read the vendor integration/API guide:** obtain endpoint/region/bucket/prefix/object pattern, read/list IAM permission, path-style and TLS. Confirm actual endpoint, auth, pagination and limits from official documentation.
2. **Prepare access:** least-privilege credentials, network/TLS access from Control, and a sanitized representative response. Never paste secrets into ChatGPT.
3. **Understand records:** 2–5 redacted examples, event root, timestamps, unique IDs, cursor and duplicate-handling rules.
4. **Prepare the Destination:** actual receiver URL/IP, port, protocol, TLS/auth and independent receipt method.
5. **Ask ChatGPT when uncertain:** provide public vendor documentation and redacted examples; request a checklist of Connector inputs, request/pagination, record root, checkpoint candidates and missing facts. Verify every answer against the vendor guide and Run Test.

### Suggested ChatGPT prompt

> I am configuring DataRelay Control's S3 Object Polling Connector. Using only the public API documentation and sanitized examples below, identify required connection/authentication fields, requests and pagination, event root, timestamp/ID checkpoint candidates, security considerations and verification. Mark anything not documented as 'needs confirmation'. Do not invent API paths or credentials.

## Follow the complete operator workflow

1. **Create Connector:** Connectors → Create Connector → **S3 Object Polling**. Enter S3 Endpoint URL, Bucket, Prefix, Object key pattern, Access key and Secret key. Save and run the available connection test.
2. **Create Destination:** Destinations → Create; select SYSLOG_UDP/TCP/TLS or WEBHOOK_POST as appropriate and enter the actual receiver's host/port/URL, TLS and auth. Prefer a controlled test sink first.
3. **Create Stream:** Streams → Create → **Connect**, select the saved Connector and set source request/file/query parameters.
4. **Sample & Record Selection:** Run Test, inspect real records, confirm record root, Union Schema, checkpoint, pagination and deduplication.
5. **Destinations:** select the saved Destination; confirm the corresponding Route exists.
6. **Route Processing:** configure field Mapping/Transform, timestamp normalization and enrichment. For sensitive fields select Mask, Remove/Drop, or **Tokenize only when the deployed version exposes and supports it**; configure Quarantine/Block when appropriate. Verify Inherit/Override and Effective Status, not only a draft preview.
7. **Deploy and run:** resolve readiness errors, deploy and explicitly start/enable the Stream when required.
8. **Prove delivery:** object listing, sample record extraction, checkpoint and sink receipt. Match exact Run ID, Route delivery log and independent Destination receipt.

### Troubleshooting and schema drift

- **Connection/auth:** inspect DNS, firewall, TLS, token scope/expiry, 401/403/429 and rate limits.
- **Zero records:** inspect actual response envelope, record root, pagination and source format.
- **Delivery failure:** follow [Delivery incident response](/use-cases/delivery-incident) from Streams → Routes → Logs.
- **New or changed fields:** inspect Union Schema Observed versus Confirmed Drift, unknown-field policy and effective Route override; follow [Schema change](/use-cases/schema-change).
- **Protection not applied:** verify supported Mask/Tokenize action, saved rule, effective status and actual receiver payload. A preview is not proof.

## 1. Prepare a controlled object

Create a test bucket in MinIO or AWS S3 and upload a file called `security/tutorial.jsonl` containing:

```json
{"id":"s3-001","message":"object event one","severity":"low"}
```

Your Control runtime must be able to reach the endpoint. Use non-production access keys with read/list permissions only; avoid embedding them in package files.

## 2. Create the Connector

1. Go to **Connectors → Create Connector → S3 Object Polling (MinIO / AWS-compatible)**.
2. Enter **Connector Name** = `Lab S3 Events`.
3. Under **S3 endpoint & bucket**, enter the actual **Endpoint URL**, **Bucket**, and **Region**.
4. Set **Prefix** = `security/` and **Object key pattern** = `*.jsonl` as a candidate filter. Adjust to your actual object paths.
5. Enter **Access key** and **Secret key** in protected Connector inputs. For MinIO use path-style addressing where appropriate. Enable HTTPS/SSL with the correct endpoint/certificates in secured environments.
6. Save and run the supported S3 connectivity/list test. Confirm the object is visible; do not assume a successful credential test implies it matches Prefix/Pattern.

## 3. Create the Stream

1. In `/streams/new`, choose `Lab S3 Events` under **Connect**.
2. In **Sample & Record Selection**, run a sample test and confirm the event is parsed as an individual JSON record.
3. Verify Event Root and schema; choose a supported checkpoint/object progression strategy appropriate to the source.
4. Select the [test HTTP Destination](/use-cases/lab-setup), review Route Processing and Deploy readiness, then start the Stream.
5. Check **Logs** plus the independent HTTP receiver file for `s3-001`.

**PASS:** the expected object is discovered, a record is extracted, and the test Destination receives the corresponding event.

## If it fails

- Empty listing: verify bucket/Prefix/Object key pattern and read/list authorization.
- TLS/endpoint failure: inspect actual MinIO/AWS regional URL and runtime network.
- Object fetched but zero events: check file structure (JSONL vs array/object) and Record Selection.
- Unexpected repeated files: inspect checkpoint/object identity and retry behavior.

# Collect Files over SFTP

**Goal:** collect events from a test file on an SSH/SFTP server. SFTP-compatible SCP mode is a specific supported option; it is **not** arbitrary legacy SCP directory polling.

## Before you start: collect SFTP integration requirements

1. **Read the vendor integration/API guide:** obtain SSH host/port, username, read-only path, host key fingerprint, password or private key, file rotation. Confirm actual endpoint, auth, pagination and limits from official documentation.
2. **Prepare access:** least-privilege credentials, network/TLS access from Control, and a sanitized representative response. Never paste secrets into ChatGPT.
3. **Understand records:** 2–5 redacted examples, event root, timestamps, unique IDs, cursor and duplicate-handling rules.
4. **Prepare the Destination:** actual receiver URL/IP, port, protocol, TLS/auth and independent receipt method.
5. **Ask ChatGPT when uncertain:** provide public vendor documentation and redacted examples; request a checklist of Connector inputs, request/pagination, record root, checkpoint candidates and missing facts. Verify every answer against the vendor guide and Run Test.

### Suggested ChatGPT prompt

> I am configuring DataRelay Control's Remote file polling Connector. Using only the public API documentation and sanitized examples below, identify required connection/authentication fields, requests and pagination, event root, timestamp/ID checkpoint candidates, security considerations and verification. Mark anything not documented as 'needs confirmation'. Do not invent API paths or credentials.

## Follow the complete operator workflow

1. **Create Connector:** Connectors → Create Connector → **Remote file polling**. Enter SFTP protocol, Host, Username, strict known-hosts policy, remote file selector. Save and run the available connection test.
2. **Create Destination:** Destinations → Create; select SYSLOG_UDP/TCP/TLS or WEBHOOK_POST as appropriate and enter the actual receiver's host/port/URL, TLS and auth. Prefer a controlled test sink first.
3. **Create Stream:** Streams → Create → **Connect**, select the saved Connector and set source request/file/query parameters.
4. **Sample & Record Selection:** Run Test, inspect real records, confirm record root, Union Schema, checkpoint, pagination and deduplication.
5. **Destinations:** select the saved Destination; confirm the corresponding Route exists.
6. **Route Processing:** configure field Mapping/Transform, timestamp normalization and enrichment. For sensitive fields select Mask, Remove/Drop, or **Tokenize only when the deployed version exposes and supports it**; configure Quarantine/Block when appropriate. Verify Inherit/Override and Effective Status, not only a draft preview.
7. **Deploy and run:** resolve readiness errors, deploy and explicitly start/enable the Stream when required.
8. **Prove delivery:** remote listing/read, parsed records, rotation/checkpoint and sink receipt. Match exact Run ID, Route delivery log and independent Destination receipt.

### Troubleshooting and schema drift

- **Connection/auth:** inspect DNS, firewall, TLS, token scope/expiry, 401/403/429 and rate limits.
- **Zero records:** inspect actual response envelope, record root, pagination and source format.
- **Delivery failure:** follow [Delivery incident response](/use-cases/delivery-incident) from Streams → Routes → Logs.
- **New or changed fields:** inspect Union Schema Observed versus Confirmed Drift, unknown-field policy and effective Route override; follow [Schema change](/use-cases/schema-change).
- **Protection not applied:** verify supported Mask/Tokenize action, saved rule, effective status and actual receiver payload. A preview is not proof.

## 1. Prepare the remote host

1. On a dedicated test SSH server, create an allowed directory such as `/srv/control-demo` and place `events.jsonl` containing:
```json
{"id":"sftp-001","message":"remote file record","severity":"low"}
```
2. Create a least-privilege read-only SSH user. Confirm the account can list and read the file using your normal `sftp` client.
3. Record the trusted server SSH host key fingerprint. Do **not** disable host verification to make a test pass.

## 2. Configure Remote File Connector

1. Choose **Connectors → Create Connector → Remote file polling (SFTP / SFTP-compatible SCP mode)**.
2. Set **Connector Name** = `Lab SFTP`, **Protocol** = `sftp`.
3. Fill in the remote **Host**, **Port** (usually 22), and **Username**.
4. Provide a permitted **Password or Private key** as supported by the form. Configure the server identity through **known-hosts** using the trusted fingerprint; choose the **strict** host-key verification policy.
5. Configure remote directory/file selection (and file pattern where offered) for `/srv/control-demo/events.jsonl`. Save, then run the supported remote connectivity/list test.

## 3. Test records and deliver

1. Create a Stream in `/streams/new`, choose `Lab SFTP`, and **Run Test**.
2. Verify a parsed record with `id=sftp-001`; use **Record Selection** to confirm the event structure.
3. Choose the [test Destination](/use-cases/lab-setup), review Route Processing and Deploy settings, and start the Stream.
4. In **Logs**, correlate the run with the independent Destination receipt.

**PASS:** SFTP listing/read succeeds, a sample record is extracted, and an independent receiver contains the corresponding event.

## If it fails

- Host verification error: fix the recorded host key and trust chain. Never switch to insecure verification to make production pass.
- Permission denied: verify the SSH account's file/directory permissions.
- No extracted records: inspect remote file encoding/format and Record Selection.
- Duplicate records: inspect source checkpoint/position and file rotation strategy.
